# Page Layout Guidelines

Reusable screen patterns for any product surface. Adapt section names and copy to the domain; keep structure and hierarchy consistent.

## Landing / Home

Objective:
- Establish product identity and primary value proposition immediately.

Structure:
1. Minimal header
2. Hero block (media, headline, or key metric) with primary CTA
3. Quick pathway strip to top destinations (2–4 links)
4. Curated preview of main content (list, cards, or highlights)
5. Short supporting narrative or feature summary
6. Minimal footer

Aesthetic checks:
- Hero content occupies major visual weight above the fold.
- CTA is present but not visually aggressive.
- No cluttered promo or notification noise.

## List / Browse

Objective:
- Present a collection in a scannable, filterable flow.

Structure:
1. Screen heading and optional subtitle
2. Category or filter controls (tab-like or chips)
3. Sort control when ordering matters
4. Content grid or list
5. Optional featured or pinned item block

Aesthetic checks:
- Grid spacing is even and quiet.
- Metadata is legible but secondary to primary content.
- Filter controls are subtle and consistent with typography.

## Detail

Objective:
- Focus attention on a single item with supporting context and actions.

Structure:
1. Back or breadcrumb navigation (when nested)
2. Primary media or data visualization
3. Title, metadata, and description
4. Secondary actions (share, favorite, edit) as quiet controls
5. Related items or next steps (optional)

Aesthetic checks:
- Primary content dominates the viewport.
- Actions do not overpower the main subject.
- Related sections use the same card language as list views.

## Catalog / Commerce (when applicable)

Objective:
- Support browsing and selection without breaking the overall visual tone.

Structure:
1. Section heading and contextual subtitle
2. Category controls + sort control
3. Grouped product or offer sections
4. Cards with consistent hierarchy (image, title, price/status, CTA)

Aesthetic checks:
- Cards follow the same visual language as generic content cards.
- Purchase or cart controls do not overpower imagery.
- Category sections feel curated, not crowded.

## Multi-Step / Workflow

Objective:
- Guide the user through a process with clarity and low friction.

Structure:
1. Context headline and short intro
2. Step indicator (typically 3–5 steps)
3. Step content (form fields, review, or confirmation)
4. Primary and secondary navigation (back, continue, submit)

Aesthetic checks:
- Steps feel editorial and purposeful, not sales-funnel heavy.
- Copy readability is high with generous line-length control.
- Forms match the rest of the app’s spacing and typography.

## Form / Contact

Objective:
- Provide a direct path to input, inquiry, or configuration.

Structure:
1. Simple heading + intro text
2. Form fields with clear labels and validation feedback
3. Submit CTA and optional alternatives (e.g. support link)

Aesthetic checks:
- Minimal distractions
- Calm, clear submission path
- Consistent typography and spacing with all other screens

## Settings / Profile (when applicable)

Objective:
- Let users manage account, preferences, or app configuration.

Structure:
1. Sectioned groups with clear headings
2. Form rows or toggles with inline help where needed
3. Destructive actions visually separated and clearly labeled

Aesthetic checks:
- Hierarchy matches list and form patterns elsewhere in the app.
- Dangerous actions are obvious but not visually loud.
